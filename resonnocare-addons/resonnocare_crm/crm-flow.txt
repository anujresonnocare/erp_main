# 🟢 STAGE 1 — LEAD CREATION

### (CRM ENTRY POINT)

![Image](https://www.images.cybrosys.com/blog/Uploads/BlogImage/how-to-create-and-manage-leads-in-odoo-18-crm-16.png)

![Image](https://www.images.cybrosys.com/blog/Uploads/BlogImage/how-to-create-a-lead-in-odoo-17-crm-11.png)

### Native Screen

**CRM → Leads → Create**

### Native Model

`crm.lead`

### What stays native

* Lead creation form
* Lead ID generation
* Source tracking (UTM)
* Assigned Salesperson

### Required Extensions (SAFE)

Add fields to `crm.lead`:

```text
x_phone (required)
x_interested_clinic_id (Many2one → res.company)
x_lead_source (Selection / Many2one)
```

### Hard Rules Enforced

✔ Phone NOT unique
✔ Name optional
✔ No OTP
✔ No patient creation
✔ No clinic lock

📌 **UI RESULT**
A normal Odoo Lead form — just richer.

## 🔹 Disposition UI (EXTENSION)

### Where it lives

👉 **Inside Lead Form (New Section)**
Not a new page.

### UI Block: **Call Disposition**

Fields:

```text
x_disposition_id (Many2one → crm.disposition)
x_attempt_count (Integer – readonly)
x_next_followup_date (Computed)
x_lead_relevant (Boolean)
```

Disposition master (NEW model):

```text
crm.disposition
- name
- follow_up_days
- max_attempts
- lead_relevant
```

📌 This maps **1:1** with your Excel sheet
📌 Sheet is COMPLETE → no edits allowed

---

## 🔹 What Happens on Save (SYSTEM LOGIC)

When agent selects Disposition:

* Call log created (`mail.message`)
* Attempt count incremented
* Next follow-up auto-computed
* Activity auto-created (if applicable)

🚫 If max attempts reached:

* Lead auto-moves to **Churned**
* Activities blocked

✔ CRM is **persistence-driven**, not conversion-driven

# 🟢 STAGE 6 — EXPECTED WALK-IN

### Native Screen (REUSED)

**CRM → Leads (Filtered View)**

Create a saved filter:

```text
Expected Walk-Ins:
- visit_intent = true
- preferred_visit_date = today
```

### Visibility Rule

* Visible ONLY to:

  * Front Desk users of that clinic
* Filtered by `x_preferred_clinic_id`

📌 CRM still OWNS the lead
📌 Front Desk only SEES it

# 🟢 STAGE 7 — FRONT DESK REGISTRATION

### (HARD BOUNDARY)

![Image](https://www.candidroot.com/web/image/7306-cc7f8283/2%20-Events.png?access_token=84cb7308-a954-41ff-bdfb-6dbac5956a9b)

![Image](https://cdn.jotfor.ms/templates/screenshot/form-templates/clinic-patient-registration-form.png?t=classic\&v=626294210)

### Module

`resonnocare_frontdesk` (already built ✅)

### Flow (UNCHANGED)

* Search by phone
* Lead detected
* OTP sent & verified
* Patient created (`res.partner`)
* Clinic locked
* Patient ID generated

### CRM Reaction (AUTOMATED)

```text
crm.lead.x_patient_id = res.partner.id
crm.lead.stage = Converted
crm.lead.conversion_date = now()
```

🚫 CRM cannot:

* Send OTP
* Create patient
* Override Front Desk
